# GMK70 project boundaries

- This repository and folder are the sole maintained source of truth for GMK70 firmware. Do not create another GMK70 repository for a new UI or firmware stack.
- Official QMK lives in `dependencies/qmk/` as an unmodified Git submodule pinned to a release tag and exact commit in `dependencies/sources.lock.json`. Initialize dependencies explicitly with `make setup`; builds must not download sources or track moving branches. Keep authoritative GMK70 board/radio sources in `firmware/qmk-common/` and QMK/VIA additions in `firmware/qmk-via/`. Build directly from these sources without copying or symlinking source trees. Keep generated headers and objects under `.work/<platform>/<variant>/<normal|updater>/`; never edit generated files or duplicate maintained board sources.
- Vial-specific additions belong under `firmware/qmk-vial/`; reuse `firmware/qmk-common/` with an independently pinned Vial fork when implementing that port. ZMK-specific work belongs under `firmware/zmk/` and requires its own hardware integration. Keep future platform sources in this repository too.
- Preserve upstream licenses, the dependency lockfile, and historical provenance in `docs/provenance/BUNDLED-SOURCES-2024.tsv` and `docs/BUNDLED-SOURCES.md`. Only GMK70 board definitions are maintained here. Avoid bulk formatting imported framework/library sources.
- Preserve `definitions/via/ZUOYA_GMK70.json` unchanged. Change firmware to match its contract; keep custom keycode values explicit and retain reserved gaps. Consult `docs/STOCK-COMPATIBILITY.md` for stock evidence and saved-map migration.
- Published build artifacts belong under `artifacts/<platform>/<variant>/`; QMK intermediates in `.work/qmk/` are disposable. `make clean` must preserve all board and library sources. Vial and ZMK targets must fail clearly until implemented, never silently produce QMK/VIA firmware under another label.
- Produce both QMK/VIA `release` and `debug` distributions with `make build`. Both implement stock V15's ordinary VIA commands, including deferred `0x0B` bootloader entry. QMK debug enables the diagnostic recorder and optional direct-USB split updater (`GMK70_DEBUG_USB_BOOTLOADER`). Vial's separate `make build-vial-updater` uses `GMK70_VIAL_UPDATE`, requires native physical unlock for writes, and excludes EEPROM queries and diagnostics. Share the board/keymap. Keep device control separate from build/test commands.
- Load the root `.env`/`.envrc` through `scripts/project.sh` before runtime/build commands. Format edited C files, run `make test`, and compile the affected supported QMK variants. Check Python tooling with its uv project, formatter, strict mypy, and dedicated tests.
- Build, test, and migration tools must not flash, reset, or write to the connected keyboard. Physical device operations are separate from this workflow.
